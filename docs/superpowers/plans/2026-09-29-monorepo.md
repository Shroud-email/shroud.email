# Shroud.email Monorepo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline execution, or superpowers:subagent-driven-development if the user selects delegation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Combine all five Shroud-email repositories into sibling directories while preserving history, builds, releases, and deployment destinations.

**Architecture:** Keep `Shroud-email/shroud.email` as the destination repository. Import unsquashed histories, relocate the app, then adapt root workflows and tooling to project-owned directories. Projects retain separate runtimes and dependencies.

**Tech Stack:** Git, GitHub Actions, mise, Elixir/Phoenix, Node/pnpm/Astro, Deno, Go/xcaddy, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-29-monorepo-design.md`

## Global Constraints

- Use sibling directories `shroud.email/`, `website/`, `hosting/`, `email-trackers/`, and `caddy-permissive-file-storage/`.
- Preserve source commits without rewriting published history; retain app tags and do not import other projects' tags.
- Preserve existing container names, app release versions, tracker-list URL, website domains, and Bunny deployment destinations.
- Keep commitlint, Husky, pinact, and zizmor at the root; retain project runtime versions and lockfiles.
- Publishing jobs must not publish containers or deploy from pull requests.
- Do not push, deploy, change GitHub secrets or settings, archive repositories, or disable existing workflows without separate authorization.
- Follow repository guidance and load relevant skills before modifying agent guidance or orb setup.

## Review Focus

1. Website-only commits must not release/build the app or cancel tracker deployments (Task 3).
2. PRs, including forks, must build without deployment secrets and never publish (Tasks 3–4).
3. A main-branch commit with no app image must not break the scheduled image scan (Task 3).
4. Hosting must compile the local plugin, even when the old plugin repository is unchanged (Task 4).
5. Import commits must not lose source files/history or accidentally change app version/tag selection (Tasks 1 and 3).
